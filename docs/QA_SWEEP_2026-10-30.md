# 전수 점검 기록 (2026-10-30)

로컬 실행(운영 DB 직결, 읽기 전용 요청)으로 확인한 결과다. 쓰기 기능(가입·신청·결제·발송·관리자 등록)은 이 문서의 2부 기능 점검 계획에 따라 TEST 데이터로 별도 진행한다.

## 1. 공개 페이지 렌더링 (자동)

- 공개 컨트롤러의 GET 매핑 전부 + 루트·sitemap·robots: 111건 요청.
- 200 정상 84건, 로그인 리다이렉트 25건(마이페이지·통합 신청 화면, 의도된 동작), 확인 필요 2건.
- 확인 필요 2건의 결론:
  - `/payment/INIstdpay_pc_req.do` 400: `@RequestBody` 를 요구하는 옛 이니시스 샘플 핸들러. 사용하지 않는 `INIstdpay_pc_return.jsp` 에서만 링크되며 실제 결제는 `/apply/payment.do` 를 쓴다. 죽은 엔드포인트(정리 대상).
  - `/sitemap.xml` 406: `Accept: text/html` 만 보낼 때의 정상 응답. 브라우저·크롤러처럼 `*/*` 를 포함하면 200 XML.
- 서버 로그: 위 2건에 대한 WARN 2줄 외 예외 없음.
- 브라우저 콘솔(메인·일정·가입·커뮤니티 상세·사진자료·교육안내·영문 메인): 404 는 모두 운영 서버 업로드 파일(`/upload/...`, `/board/uploadFileGet?...`)이라 로컬에서만 발생. 스크립트 오류 없음.
- 운영의 배너 이미지가 `/upload/pop/banner/...` 로 직접 서비스되는 것으로 보아 `webapps/upload` 는 Tomcat 컨텍스트로 배포돼 있다. 업로드 확장자 차단(보안 조치 C-3)이 실제로 필요한 구조.

## 4. 관리자 페이지 렌더링 (브라우저, 관리자 로그인 세션)

- 관리자 컨트롤러의 GET 화면 84건(목록·상세·등록 화면, 엑셀·통계 API 제외)을 로컬 브라우저에서 순서대로 열어 확인.
- 84건 모두 관리자 레이아웃과 본문이 렌더링됐고, 목록 화면의 조회 API(`.../selectList.do`)도 200 으로 응답. 세션 검사 인터셉터가 관리자 세션을 정상 통과시킴.
- 서버 로그 예외 0건. 브라우저 콘솔 404 는 공개 페이지 점검 때의 업로드 파일 22건 그대로이며 관리자 화면에서 새로 발생한 것은 없음. Metronic 자산·폰트·관리자 JS 전부 200.
- 상세 화면을 seq 없이 열면 신규 등록 양식이 나온다(정상). 이력서 상세는 관리자 레이아웃 없이 양식만 출력되는 별도 화면.
- 눈에 띄는 문구 불일치(기능 영향 없음): `customer/sterndrive/detail.jsp` 제목 "Sterndrive 정비", `customer/sternspecial/detail.jsp` 와 `customer/unified/detail.jsp` 의 상단 제목이 "자가정비 심화과정 (고마력)" 으로 복사된 채 남아 있음. 퍼블리싱 정리 때 함께 수정 권장.
